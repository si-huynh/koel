## Deferred from: Story 1.4 implementation (2026-05-28)

- **`custom_lint` 0.8.1 workspace-mode include resolution is broken — consumer plugin chain does not fire `exhaustive_switch_must_have_default`** — Root cause confirmed via `~/.pub-cache/.../custom_lint-0.8.1/lib/src/workspace.dart:333-341`: `visitAnalysisOptionAndIncludes` reads `package_config.json` from `analysisOptionsFile.parent.path/.dart_tool/`, which in pub-workspace mode is **empty** for workspace members (the real `package_config.json` lives only at the workspace root). The `package:` URI in `include: package:koel_lints/koel.yaml` cannot be resolved, the include chain breaks after yielding only the consumer's 2-line yaml, that yaml has no `analyzer.plugins:` declaration, `_isCustomLintEnabled` returns `false`, the project is silently skipped, and the rule never runs. Verified empirically: `dart run custom_lint` from `packages/koel_core/` returns `No issues found!` on a deliberately-failing `switch (e) over AgUiEvent` fixture. The same fixture content fires the rule under `koel_lints`'s `testAnalyzeAndRun` harness (Story 1.3's 4 tests stay green) — so the rule logic itself is correct; only the consumer plugin-discovery path is broken. **Closes Story 1.3 deferred-work entry "`custom_lint.rules:` YAML syntax for 0.8.1 not end-to-end verified via consumer plugin path"** — that entry was the prediction; this is the confirmation. **AC3 plugin-discovery gate is unfulfilled.** Story 1.4 ships the include-+-dev-deps wiring (target state once upstream is fixed); `melos run analyze` zero-warning gate still holds (NFR-13 met). Workaround options considered and rejected for v1.0.0 scope: (a) inline `analyzer.plugins:` + `custom_lint.rules:` per consumer — violates AC1 2-line shape, 10-file edit per rule; (b) symlink per-member `.dart_tool/package_config.json` to workspace root — fragile under `melos bootstrap`, non-idiomatic. **Re-verify when:** a `custom_lint` release fixes workspace package_config resolution (track pub.dev for 0.8.2 / 0.9.x); or when the consumer plugin path is exercised via a non-workspace integration smoke test in CI (e.g. `dart create` a throwaway consumer, add `koel_lints` as a `hosted:` dep via a local pub server). Until then, `exhaustive_switch_must_have_default` is enforced only inside `koel_lints` unit tests, not on consumer source — Epic 2+ implementers should be made aware in Story 1.6 README polish.

Fixture file deleted from working tree; `git status` clean of `_verify_lint.dart` / `verify_lint.dart`. Re-run Task 6 when the underlying `custom_lint` workspace bug is fixed.

Spec consciously chose this via AR-1 ("one lint baseline") and the Dev Notes anti-pattern list explicitly forbids re-adding `flutter_lints`. **Action — before Epic 4 widget stories land:** either (a) merge curated Flutter rules into `koel_lints/lib/koel.yaml`, or (b) ship a `koel_lints/lib/koel_flutter.yaml` variant that extends `koel.yaml` + Flutter rules, switching the 3 Flutter packages' `analysis_options.yaml` to include it. Track alongside `koel_lints` rule-pack expansion in v1.x.
