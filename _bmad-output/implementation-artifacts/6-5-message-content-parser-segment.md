# Story 6.5: `MessageContentParser` + sealed `MessageSegment`

## Story

As a Flutter developer,
I want `MessageContentParser` splitting assistant message strings into `List<MessageSegment>` (sealed: `TextSegment | CodeBlockSegment`) with markdown-fenced code-block detection,
so that I can render mixed prose + code without inline parsing logic per FR-E1.

## Context & scope (read first)

This is the **first Group-E (message content) deliverable** in `koel_flutter` and the **fifth public symbol** in the package (after `KoelChatController`, `KoelClientScope`, `HiveSessionStorage`, `SecureSessionStorage`). It is **single-package** (`koel_flutter` only), **pure `dart:core`** — no new dependency, no `koel_core` change, no codegen (koel_flutter has no `build_runner`/`freezed` — [pubspec.yaml dev_deps](../../packages/koel_flutter/pubspec.yaml)). The whole job is: a small sealed value-type union (`MessageSegment` → `TextSegment` / `CodeBlockSegment`), a hand-written line-based markdown-fence parser, the barrel lines, tests (contract + edge + property-based), and **one integration test proving the `koel_lints` rule fires on `MessageSegment` switches**.

Two things make this story more than "split a string":

1. **`MessageSegment` is the third member of `koel_lints`' `_sealedNames` registry** — alongside `AgUiEvent` and `KoelError` ([exhaustive_switch_must_have_default.dart:29](../../packages/koel_lints/lib/src/rules/exhaustive_switch_must_have_default.dart#L29)). The rule was authored in Story 1.7 with `MessageSegment` **forward-declared** — this story makes that type real. The rule matches **by simple type name** (`expr.staticType?.element?.name == 'MessageSegment'`, [line 44-47](../../packages/koel_lints/lib/src/rules/exhaustive_switch_must_have_default.dart#L44)), is **`error` severity**, and is **enabled workspace-wide** ([/analysis_options.yaml:3-7](../../analysis_options.yaml#L3)). Consequence: the moment `MessageSegment` exists, **any `switch` over it in koel's own code or tests that lacks `default:` fails `melos run analyze`** (see **D6**). AC1 additionally requires an *integration test* that proves the rule fires — see **D4**.

2. **The parsing semantics are the real design weight.** The epic's BDD ([epic-6:107-122](../planning-artifacts/epics/epic-6-flutter-glue-persistence-koelflutter.md#L107)) gestures at "markdown-fenced code-block detection," "inline backticks stay text," and "edge cases never crash" but does not pin the algorithm. **D3 is the locked parsing contract** — read it before writing a line. FR-E1 deliberately scopes this to *fenced code blocks only*; image embeds and rich content defer to the future `koel_a2ui` package (v2) — do not build them ([prd.md FR-E1:170](../planning-artifacts/prds/prd-koel-2026-05-27/prd.md#L170)).

The deliberately small surface (`MessageContentParser.parse` + the sealed union — [addendum A.6:417-426](../planning-artifacts/prds/prd-koel-2026-05-27/addendum.md#L417)) follows the same A.6-exact discipline as 6.1–6.4. Read **Dev Notes → Design decisions (D1–D8, locked)** before writing any code.

2. **Prose + multiple fenced code blocks parse to an alternating, language-preserving segment list; inline backticks stay text (AC source: [epic-6:115-118](../planning-artifacts/epics/epic-6-flutter-glue-persistence-koelflutter.md#L115)).** Given a content string containing prose interleaved with **three fenced code blocks of different languages**, `parse` returns an **alternating** `List<MessageSegment>` of `TextSegment`/`CodeBlockSegment` instances, each `CodeBlockSegment` carrying its language hint (D3) and verbatim code body, each `TextSegment` carrying the verbatim prose run. **Unfenced backticks** — single/double inline-code spans like `` `foo()` `` mid-line — remain **inside** a `TextSegment` (only line-leading fences of ≥3 backticks split out, per FR-E1's deferral of rich content). A test asserts the exact segment sequence, types, languages, and code bodies.

3. **Every edge case produces well-formed output and the parser is total (AC source: [epic-6:120-122](../planning-artifacts/epics/epic-6-flutter-glue-persistence-koelflutter.md#L120)).** Each of these returns a well-formed `List<MessageSegment>` and never throws: empty string (→ `[]`, D3), code block at start (→ list begins with `CodeBlockSegment`), code block at end (→ list ends with `CodeBlockSegment`), **unclosed** code block (opening fence with no closing fence → one `CodeBlockSegment` running to EOF, D3), and a language-tagged fence with **no body** (→ `CodeBlockSegment(language: <tag>, code: '')`). Additionally a **property-based test** over **500 seeded-random markdown-ish strings** (D8) asserts the parser **never crashes** and upholds the structural invariants: no `TextSegment` has empty `text`, and no two adjacent segments are both `TextSegment` (the alternation guarantee from AC2).

## Dev Notes

### Design decisions (locked — implement as stated)

- **D1 — Hand-written sealed union, NO freezed/codegen; `part`/`part of` 3-file layout.** `koel_flutter` has **no `build_runner`/`freezed`** ([pubspec.yaml](../../packages/koel_flutter/pubspec.yaml) — confirmed: dev_deps are `koel_lints`/`flutter_test`/`koel_test`/provider/bloc/riverpod/get only). So `MessageSegment` is **hand-written**, unlike `koel_core`'s freezed unions. Use the **AgUiEvent part/part-of pattern** ([ag_ui_event.dart](../../packages/koel_core/lib/src/event/ag_ui_event.dart) — sealed root in one file, subtypes as `part of` files) because the architecture source tree explicitly lists three files (`message_segment.dart # sealed`, `text_segment.dart`, `code_block_segment.dart` — [architecture.md:903-906](../planning-artifacts/architecture.md#L903)) and Dart requires sealed subtypes to live in the **same library**. `message_segment.dart` is the library root with the `sealed class` + two `part` directives; the leaf files open with `part of 'message_segment.dart';`. Give the leaves hand-written `==`/`hashCode`/`toString` — these are value types compared in tests; hand-rolled equality is the faithful equivalent of freezed's generated value-semantics, and is **not** a surface expansion (Object overrides, not new API). This keeps the package codegen-free (no `build.yaml`, no `*.freezed.dart`).

- **D2 — `final class` leaf subtypes (A.6's `class` is illustrative shorthand).** A.6 writes `class TextSegment extends MessageSegment { final String text; ... }` with `...` standing in for the body — illustrative, not a literal modifier mandate. Use `final class` for both leaves: (a) they are **leaf value types** never meant to be subclassed — `final` is the strongest misuse-prevention ("design for what users *can't* misuse," CLAUDE.md), (b) parity with `koel_core`'s sealed-subtype discipline (its freezed subtypes are effectively final/closed), (c) `final` does not change the public field/constructor surface A.6 pins. The sealed root keeps only `const MessageSegment();`.

- **D3 — The parsing contract (locked algorithm). Backtick-fenced code blocks only; line-based; lossy on fence markers, total on input.** Implement **exactly** this; do not gold-plate toward full CommonMark.
  - **Lines.** Treat `content` as lines separated by `'\n'` (the separator is not part of a line). Process line by line, tracking a `text` vs `code` mode.
  - **Opening fence (text mode only).** A line is an opening fence iff, after **≤3 leading spaces**, it begins with a run of **≥3 backticks** (`` ``` ``). Capture `fenceLen` = backtick-run length and `info` = the remainder of the line **trimmed**. The **`language`** of the resulting `CodeBlockSegment` is `info` (trimmed; `''` when the fence carried no info string). *(Keep the whole trimmed info string — lossless and unambiguous; the rare multi-word info string like `dart title=x` is preserved as-is for the consumer to split. Do not split on whitespace.)*
  - **Closing fence (code mode only).** A line is the closing fence iff, after ≤3 leading spaces, it is a run of **≥ `fenceLen` backticks** followed by **only optional trailing whitespace** (no info string). The closing fence line is **consumed** (added to neither segment).
  - **Code body.** The content lines strictly between the opening and closing fence, **joined by `'\n'`**. `` ```dart\nfoo\nbar\n``` `` → `code == 'foo\nbar'`. Open-then-immediate-close → `code == ''`.
  - **Unclosed fence.** If EOF is reached in code mode, flush a `CodeBlockSegment(language, code = accumulated body)` — the block runs to EOF (CommonMark behavior).
  - **Text runs.** Accumulated text-mode lines (joined by `'\n'`) flush as a `TextSegment` **only when non-empty**. Suppressing empty text runs is what guarantees AC2's alternation (code-at-start, code-at-end, and adjacent fences emit no empty `TextSegment`).
  - **Inline backticks.** Because a fence must be a line that is *only* ≤3 spaces + a backtick run (+ info), a line like `` use `foo()` here `` (leading non-backtick text) never matches — inline code stays inside its `TextSegment`, satisfying FR-E1's deferral of rich content.
  - **Empty input.** `parse('')` → `[]`.
  - **Out of scope (deliberate, faithful to FR-E1):** tilde (`~~~`) fences (treated as text), indented-4-space code blocks, inline-code segmentation, images/rich content (→ `koel_a2ui` v2). Do not implement these.

- **D4 — AC1 lint verification = a koel_flutter-local integration test mirroring `dart_analyze_fires_test.dart`.** The rule is already enabled workspace-wide and already lists `MessageSegment` in `_sealedNames` ([line 29](../../packages/koel_lints/lib/src/rules/exhaustive_switch_must_have_default.dart#L29)); it matches **by simple type name** ([line 44-47](../../packages/koel_lints/lib/src/rules/exhaustive_switch_must_have_default.dart#L44)). AC1 asks this be *"verified by integration test."* The established integration idiom for this rule is the **`dart analyze` process-spawner** ([koel_lints/test/integration/dart_analyze_fires_test.dart](../../packages/koel_lints/test/integration/dart_analyze_fires_test.dart)): a temp package built **outside** the workspace (because `plugins:` is rejected in workspace-nested options — `plugins_in_inner_options`), the plugin enabled by absolute path, `dart analyze` run over a `switch`-without-`default:`, asserting **exactly one** `exhaustive_switch_must_have_default` hit. Build the 6.5 test the same way but with an **inline `sealed class MessageSegment`** fixture. **Rationale for koel_flutter-local placement:** every 6.x story kept its proofs in its own package; this gives koel_flutter a real regression guard tied to *this story's* introduction of `MessageSegment` and confirms the registry entry is live, without a cross-package edit to koel_lints. **Rejected alternative:** extending koel_lints' own integration test to parametrize all three sealed names — it lives in the rule's home but (a) makes a koel_flutter story modify koel_lints, and (b) the rule's *firing mechanism* is already proven there for `AgUiEvent`; what 6.5 needs to prove is that `MessageSegment` (this story's new type) is caught. The inline fixture is the correct technique (not a shortcut) precisely because the rule keys on the simple name — importing the real koel_flutter type is impossible anyway (the fixture must live outside the workspace).

- **D5 — No new dependency; pure `dart:core`.** Parsing is plain Dart string/line work — no package needed. Do **not** add a markdown package (over-dependency; FR-E1 is a deliberately narrow fenced-block split, not a markdown renderer). `pubspec.yaml` is untouched, `pubspec.lock` must not drift, and the AI-5.9 pins (`analyzer 12.1.0` / `freezed 3.2.6-dev.1`) hold trivially. This is the lightest-footprint story in Epic 6.

- **D6 — koel's own code/tests must never `switch` over `MessageSegment` without `default:`.** The rule is `error` severity and enabled workspace-wide ([/analysis_options.yaml:3-7](../../analysis_options.yaml#L3)); the instant `MessageSegment` exists, any `switch` over it lacking `default:` **fails `melos run analyze`** — including koel_flutter's own library and test code. The parser itself produces segments and need not switch over them. In tests, use `is TextSegment`/`is CodeBlockSegment` checks, or pattern-match **with `default:`**. This is the friction the rule is designed to create for consumers (forward-compat), and koel eats its own dog food. Keep `analyze` green by never writing a defaultless `MessageSegment` switch outside the deliberate Task 4 fixture (which lives in a temp package, not in the analyzed workspace).

- **D7 — A.6-exact surface.** Public surface is **only**: `MessageContentParser` + `List<MessageSegment> parse(String)`; `sealed class MessageSegment` (const ctor); `final class TextSegment` (`text`); `final class CodeBlockSegment` (`language`, `code`). No inline-code segment type, no tilde-fence support, no parser config knobs, no `MessageSegment.parse` static, no extra factories. Same discipline as 6.1 (dropped `tools`), 6.2 (omitted `maybeOf`), 6.3 (no `open` factory), 6.4 (no `clearAll`). `==`/`hashCode`/`toString` on the leaves are value-semantics Object overrides, not surface additions (D1).

- **D8 — Property test via seeded `Random` (mirror the koel_core idiom), not an external package.** The repo has **no** property-testing dependency (no glados/fast_check). The established idiom is a fixed-seed `dart:math` `Random` drawing from a generator, asserting invariants — see [error_classifier_test.dart:167](../../packages/koel_core/test/error/error_classifier_test.dart#L167) (`Random(0xC0FFEE)`) and [koel_http retry_interceptor_test.dart](../../packages/koel_http/test/retry_interceptor_test.dart) (`Random(1)`/`Random(7)`). Seed once with a fixed value for determinism, generate 500 markdown-ish strings (interleave random short prose tokens, `'\n'`, backtick runs of length 1–5, and optional language tags), and assert the AC3 invariants (no-throw, no empty `TextSegment`, no two adjacent `TextSegment`s). Do **not** add a dependency for this (parity with D5).

### Sealed-union pattern reference (the layout to mirror)

`AgUiEvent` ([ag_ui_event.dart](../../packages/koel_core/lib/src/event/ag_ui_event.dart)) is the part/part-of template: `sealed class AgUiEvent { const AgUiEvent(); … }` in the root file, subtypes in sibling files opening with `part of 'ag_ui_event.dart';`. **Differences for `MessageSegment`:** no freezed (D1 — hand-written `==`/`hashCode`/`toString`), no `fromWire`/codec (not persisted, not wire-decoded — it is a *render-time* split of an already-decoded assistant string), and a closed 2-leaf set (like `KoelError`'s 4-leaf closed set, but split across files per the architecture tree). `KoelError` ([koel_error.dart](../../packages/koel_core/lib/src/error/koel_error.dart)) shows the inline-closed-set variant — useful context, but follow the **part-based** AgUiEvent layout here to match the architecture's three-file source tree.

### `ChatState` / message provenance (where parser input comes from — context only, nothing to change)

`MessageContentParser.parse` takes a raw assistant **string** (the accumulated `Message` content from `ChatState.messages` after a run completes) and is a **pure render-time helper** — it does not touch `koel_core`, `ChatState`, the reducer, or storage. There is no coupling to the persistence codec (6.3/6.4) — segments are derived on demand for display, never stored. This is why the story is single-package and dependency-free.
