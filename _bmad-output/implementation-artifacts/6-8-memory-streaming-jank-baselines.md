4. **The 1.x contract seal** — confirm the barrel `lib/koel_flutter.dart` exports exactly the PRD §9 / Addendum A.6 surface (it already does — this is *verify, don't rewrite*), then extract + commit the `dart_apitool` baseline Epic 9 will diff against (AR-12 / D7).

**The three traps the epic AC doesn't tell you (resolved in D1–D3):**

1. **The benches must run under `flutter test`, not `dart test`** — `koel_flutter` depends on the Flutter SDK, so `dart test` can't load it. The koel_core harness imports `package:test/test.dart`; the koel_flutter copy **must** import `package:flutter_test/flutter_test.dart` (D1).
2. **`flutter_tester` does not rasterize on a real GPU** — so `streaming_jank_bench` **cannot** measure literal "frames under 16 ms" the way the AC's wording implies. The deterministic, host-runnable proxy is the **synchronous UI-thread work per streamed event** (the work that *would* consume a frame budget). Real device frame-jank is the Epic 9 / AR-17 device-matrix concern, where BENCHMARKS.md's reference-device profile lives (D3).
3. **`flutter test --coverage` is a different mechanism than `dart test --coverage`** — it emits `coverage/lcov.info` natively (no `format_coverage`, no `--branch-coverage`). `tool/coverage.sh`'s dart-test body won't run a Flutter package; it needs a flutter branch (D4).

## Dev Notes

### Design decisions (locked — implement as stated)

- **D1 — The benches run under `flutter test`; copy `perf_baseline.dart` but import `flutter_test`.** `koel_flutter` declares `flutter: { sdk: flutter }` ([pubspec.yaml](../../packages/koel_flutter/pubspec.yaml)), so `dart test` cannot load it (no engine binding) — `tool/test_package.sh` routes it to `flutter test` (since 6.1). `flutter test` runs on `flutter_tester`, a host Dart VM **with `dart:io`** — so `ProcessInfo.currentRss`, `File`, and `Platform.version` (which `recordOrGate` uses) all work. The koel_core harness imports `package:test/test.dart`; the koel_flutter copy **must** import `package:flutter_test/flutter_test.dart` (it re-exports `expect`/`fail`/`lessThanOrEqualTo` from `package:matcher`/`package:test_api`). Everything else in [`perf_baseline.dart`](../../packages/koel_core/test/perf/perf_baseline.dart) is byte-identical — copy it, don't re-derive. (Per-package copy is the established pattern — koel_http copied it from koel_core; it's a `test/` helper, not cross-package-importable.)

- **D2 — `chat_session_memory_bench`: RSS-delta via `ProcessInfo.currentRss` over a large fixed sequence, plain `test` (no widget).** N-3 ([prd.md:295-296](../planning-artifacts/prds/prd-koel-2026-05-27/prd.md#L295)): "No regression > 10% vs the v1.0.0 baseline RSS delta when running the `chat_session_memory_bench` script (single active session over a fixed event sequence). **Excludes consumer-held message history.**" So: one `ChatSession`/`KoelChatController`, a **fixed** event run, `ProcessInfo.currentRss` before/after. RSS is GC-noisy and KB-scale on a short run — so use a **large** fixed sequence (thousands of events) and record `percentile(deltas, 99)` over many iterations, exactly the "large N → stable, regression-sensitive, non-flaky" rationale reducer_bench uses (3000 sweeps, [reducer_bench.dart:33-36](../../packages/koel_core/test/perf/reducer_bench.dart#L33)). Default log-only mode means local GC noise never flakes the suite; the >10% gate is the Epic-9 reference-device path. No widget needed — `KoelChatController` (a `ChangeNotifier`) and `ChatSession` construct without a binding; keep it a plain `test` so the metric isolates koel's data-structure footprint, not Flutter render allocations. Metric key `rss_delta_bytes`, lower-is-better.

- **D3 — `streaming_jank_bench`: synchronous per-event UI-thread work via `testWidgets` + Stopwatch, NOT real frame raster.** N-5 ([prd.md:297](../planning-artifacts/prds/prd-koel-2026-05-27/prd.md#L297)) is, in its own words, about *"No protocol work runs synchronously on the UI thread … Frame jank during continuous streaming stays below the 16 ms budget."* The jank-relevant quantity is the **synchronous work that lands on the caller's isolate per streamed event** (reduce → `notifyListeners` → rebuild) — the work that *would* blow a frame. `flutter_tester` does **not** rasterize on a real GPU; `FrameTiming` raster numbers there are synthetic, so a literal "frames over 16 ms" measurement is **not** obtainable in `flutter test` — that's the Epic 9 / AR-17 device-matrix concern, where the BENCHMARKS.md reference-device profile lives ([architecture §10 CI-matrix](../planning-artifacts/architecture.md), AR-15). The faithful, deterministic, **host-runnable** proxy: drive a continuous fixed-length stream through a `KoelChatController`-bound `AnimatedBuilder` and `Stopwatch` the synchronous rebuild+notify work per delta; record `p99_frame_micros` and log the count exceeding the 16 ms budget. **This is the same "the AC names an illustrative mechanism; the source-true, host-runnable choice wins" call as 6.1/D1, 6.5/D2, 6.6/D1, and 6.7** (where the device matrix was likewise deferred to Epic 9). Record the real-device-raster deferral in `deferred-work.md`.

- **D4 — Coverage: add a `sdk: flutter` branch to `tool/coverage.sh` (`flutter test --coverage`).** [`tool/coverage.sh`](../../tool/coverage.sh) runs `dart test --coverage=coverage --branch-coverage` then `format_coverage` — neither works for a Flutter package. `flutter test --coverage` writes `coverage/lcov.info` **natively** (no `format_coverage` step) and has **no** `--branch-coverage` flag. Extend the script exactly as `test_package.sh` routes: `if grep -q "sdk: flutter" pubspec.yaml` → `flutter test --coverage --exclude-tags=perf`, then run the **existing** awk gate over `coverage/lcov.info`. The awk already handles a missing branch table (`branch=(brf>0)?…:100`), so passing `90 90` enforces **line ≥ 90** and lets branch pass trivially (flutter emits no `BRDA`). Pure-Dart packages keep the current path byte-for-byte. The `with_chrome` merge is koel_http-specific (conditional web transport) and does **not** apply — koel_flutter's web tests, if any, are inside the `flutter_test` suite.

- **D5 — Coverage tier = 90% line (Epic AC4 + header), stricter-satisfies the PRD floor.** Epic 6 header ([epic-6:3](../planning-artifacts/epics/epic-6-flutter-glue-persistence-koelflutter.md#L3) "Coverage ≥ 90%") and AC4 ([epic-6:199](../planning-artifacts/epics/epic-6-flutter-glue-persistence-koelflutter.md#L199) "coverage ≥ 90% per NFR-12 (foundation tier per architecture)") govern this story. PRD N-12 ([prd.md:315](../planning-artifacts/prds/prd-koel-2026-05-27/prd.md#L315)) classifies non-foundation packages at ≥80%. **90% ⊇ 80%**, so locking 90 cannot violate the PRD floor — the parity-safe call (and the explicit AC). koel_flutter already ships 74 tests across every feature, so 90% line is reachable. **FYI (not a question):** if a genuinely untestable symbol blocks 90 in `flutter_tester`, surface it as a dev finding with the 80% PRD floor as the documented fallback — do **not** silently lower the gate (house rule: own-the-gate).
