[Source: transport.dart:1-43; web_transport.dart:1-11]
> 2. **`WebTransport.connect` must return the SAME `TransportResponse` shape native returns** — `{int statusCode, Stream<List<int>> body, Future<void> Function() abort}` ([transport.dart:45-73](packages/koel_http/lib/src/transport/transport.dart)). `HttpAgent`/`_TransportTerminal` consume `TransportResponse` *uniformly* ([http_agent.dart:204-278](packages/koel_http/lib/src/http_agent.dart)) — they never know which platform produced it. So: `fetch(url, {method:'POST', headers, body, signal})` → `Response.status` is `statusCode`; `Response.body` (a `ReadableStream`) → drained into a `StreamController<List<int>>` whose stream is `body`; `AbortController.abort()` (wrapped) is `abort`. ## Dev Notes

### What this story is, in one paragraph

The epic-sealing story makes `koel_http` work on web and lands the package's release gates. The web transport replaces the throwing `web_transport.dart` stub with a real `package:web` `fetch` + `ReadableStream` + `AbortController` implementation that returns the **same `TransportResponse`** native returns — so every layer above the seam (auth headers, retry, chunk synthesis, SSE parse, lifecycle hooks, `abortOnCancel` <50 ms cancellation, the non-2xx throw path) works on web for free, with zero web-specific business logic. `EventSource` is forbidden (D4: it can't set the `Authorization` header). CI grows a macOS native job and a headless-Chrome web job (NFR-11). The `sse_parse_bench` captures the N-1 parse-throughput baseline via the proven `recordOrGate` harness (copied per-package), recording per-event microseconds (lower-is-better) with a >10% regression gate under `KOEL_PERF_GATE`. The finalization gates — `public_member_api_docs` member-doc `analysis_options.yaml`, the ≥90% coverage gate (`coverage_options.yaml` + the `test:coverage` line), `dart analyze` exit 0 — seal the package. Scope: **1 MODIFY (`web_transport.dart` stub→impl) + 1 pubspec dep + 2 NEW tests (browser + perf) + 1 NEW perf helper + 1 CI MODIFY + 3 finalization files (2 NEW + 1 MODIFY).** No `koel_core` change, no seam redesign, no new freezed type.

### Where the web transport plugs in (the seam that makes everything-above free)

```
HttpAgent.run ─► InterceptorChain[ Retry(4.4) ─► Auth(4.5)/… ─► _TransportTerminal ]
                                                                      │ connect() ── platform-selected via conditional import
                          dart.library.io  ─► IoTransport (dart:io HttpClient)      ─┐
                          dart.library.js_interop ─► WebTransport (THIS STORY)       ├─► returns TransportResponse{statusCode, body:Stream<List<int>>, abort}
                          (neither)        ─► transport_stub (throws)               ─┘
                                                                      │
   _TransportTerminal consumes TransportResponse identically on both platforms:
     connect() → onConnect (4.9) → non-2xx? disconnect+throw (4.2) → SseParser.parse (4.1)
     → chunksStage (4.8) → track (4.9 onDisconnect) → abortOnCancel(…, response.abort) (4.3 <50ms)
```

- The web transport supplies `statusCode`/`body`/`abort`; the terminal does the rest. **All AG-UI semantics live above the seam and are platform-agnostic.** [Source: http_agent.dart:204-278; transport.dart:20-73]

### `package:web` 1.1.1 streaming API (verified against installed source)

The risky, least-familiar surface. Confirmed signatures in `~/.pub-cache/hosted/pub.dev/web-1.1.1/lib/src/dom/`:

- **fetch** — `Window.fetch(JSAny input, [RequestInit init]) → JSPromise<Response>`. `RequestInit` (`fetch.dart`) carries `method`, `headers` (HeadersInit — a `Headers` object or a JS record), `body`, and `signal` (`AbortSignal?`, `fetch.dart:388-389`). Build via `Window`/`globalContext`. `await promise.toDart` yields a `Response`.
- **Response** — `Response.status` (int) → `statusCode`; `Response.body` → `ReadableStream?` (`fetch.dart:613`).
- **ReadableStream** (`streams.dart:39`) — `getReader()` → `ReadableStreamReader` (cast to `ReadableStreamDefaultReader`, `streams.dart:204`). `ReadableStreamDefaultReader.read()` → `JSPromise<ReadableStreamReadResult>` (`streams.dart:210`); `ReadableStreamReadResult` has `.done` (JSBoolean) + `.value` (`JSAny?`, a `JSUint8Array` for a byte stream) (`streams.dart:254-260`); `reader.cancel([reason])` (`streams.dart:244`).
- **AbortController** (`dom.dart:549`) — `AbortController()`; `.signal` → `AbortSignal` (`dom.dart:562`); `.abort([reason])` (`dom.dart:557`).
- **JS↔Dart bridges** (`dart:js_interop`): `String.toJS`, `Uint8List.toJS`/`(jsUint8Array).toDart`, `JSPromise.toDart`, `JSBoolean.toDart`. The read loop: `final r = await reader.read().toDart; if (r.done.toDart) break; controller.add((r.value! as JSUint8Array).toDart);`.

Per CLAUDE.md "read framework source, not just docs" — these are read off the installed 1.1.1 source, not docs. [Source: web 1.1.1 `lib/src/dom/{fetch,streams,dom}.dart`; [package:web ReadableStream docs](https://pub.dev/documentation/web/latest/web/ReadableStream-extension-type.html)]

### Cancellation on web (Gap G-1, NFR-8)

`abortOnCancel` (4.3) calls `response.abort()` the instant the consumer cancels, fire-and-forget, enforcing <50 ms ([cancellation.dart:50-83](packages/koel_http/lib/src/connection/cancellation.dart)). On web, `abort` = `AbortController.abort()` (aborts the in-flight fetch + stream read at the browser level — the web analogue of native's socket destroy) + cancel the reader + close the controller. **Idempotent** and safe after done (native's `abort` honors the same contract). Architecture G-1 explicitly names `AbortController` as the web cancellation primitive and asks for it in the `web_transport.dart` doc contract — document it. The browser cancel test measures the same `cancel()`→teardown delta the native `cancellation_test` does. [Source: cancellation.dart:50-102; architecture.md:1198-1202; transport.dart:61-72]

### Web error classification (consideration — NOT a required task)

On web, a fetch network failure throws a JS `TypeError`/`DOMException`, not a `dart:io` `SocketException`. The transport-level [error_classifier.dart](packages/koel_http/lib/src/error/error_classifier.dart) routes non-`dart.library.io` platforms to [error_classifier_stub.dart](packages/koel_http/lib/src/error/error_classifier_stub.dart) → `DefaultErrorClassifier` (by-name matching). That base **prevents uncaught escapes** (any thrown error becomes a terminal `RunErrorEvent`, satisfying the 4.2 AC4 "no uncaught exception"), but a web network failure will bucket as `transportClosed`/`unknown` rather than the precise `transportRefused`/`transportTlsFail` native gets. **This is acceptable for 4.10** — precise web error codes are a future refinement and the ACs do not require them. Add a `web_error_classifier.dart` (refining JS failure shapes) **only if** the ≥90% coverage gate cannot otherwise be met on the VM-coverable surface — it should not be needed, since the classifier seam is VM-covered via the native path. Do not build it speculatively (no "just-in-case" code, per CLAUDE.md). [Source: error_classifier_stub.dart; error_classifier.dart; 4-2 AC4]

### Perf bench: why per-event microseconds, not raw events/sec (RESOLVED — trap #10)

The proven `recordOrGate` harness is **lower-is-better** (`value > baseline * 1.10` fires the regression). Throughput (events/sec) is higher-is-better — inverting the gate sense. Rather than fork the harness, record the **per-event duration in microseconds** (`p99_micros_per_event`), exactly as `reducer_bench` does; "events-per-second throughput" (the AC's words) is the derived human-readable figure (`1e6 / micros`) logged alongside. Same metric, gate sense preserved, harness reused verbatim. The harness is copied into `koel_http/test/perf/perf_baseline.dart` because koel_core's lives under `koel_core/test/` and imports `package:koel_core/src/` internals — not cross-package importable; the `percentile`/`recordOrGate` functions are pure `dart:io`+`dart:convert` with no koel_core coupling, so the copy is clean. [Source: perf_baseline.dart:43-106; reducer_bench.dart:68-90]

### `onDisconnect` cause / lifecycle on web

Inherited from 4.9, unchanged: `onConnect` fires when `connect()` returns (web: fetch resolved, headers in); `onDisconnect` fires once on stream end (done `null` / error cause / cancel `null` / non-2xx `TransportError`); a pre-headers fetch rejection fires neither. The web transport just needs `connect()` to resolve/throw at the right boundary — the terminal does the lifecycle (trap #2). [Source: 4-9 Dev Notes; http_agent.dart:217-249]

### Completion Notes List

**What shipped.** The throwing `web_transport.dart` stub is now a real `final class WebTransport implements Transport` using `window.fetch` + `ReadableStream` + `AbortController` via `package:web`, returning the byte-for-byte same `TransportResponse` native returns — so auth headers, retry, chunk synthesis, the SSE parse, lifecycle hooks, the non-2xx throw, and `abortOnCancel`'s <50ms cancellation all work on web with zero web-specific business logic. Proven against a **real** `fetch` in headless Chrome by a `spawnHybridUri` mock-server browser test (header flow, mid-stream cancel + real TCP teardown, non-2xx parity). CI grows a macOS native job + a headless-Chrome web job. `sse_parse_bench` captures the N-1 baseline via a copied `recordOrGate` harness. Package-finalization gates landed: member-doc `analysis_options.yaml`, `coverage_options.yaml`, the `test:coverage` 90/90 `with_chrome` line.

**Design choices (specialist judgment):**
- **`WebTransport` body is an `async*` generator**, not a hand-rolled `StreamController` mirroring `io_transport.dart`'s `_Connection`. A pull-based `ReadableStream` reader maps naturally onto `async*`: it gives backpressure, pause/resume, and cancel-runs-`finally` for free. The explicit idempotent `abort()` (the `AbortController.abort()` G-1 primitive) is what `abortOnCancel` drives for the <50ms budget; the `finally` is the slow/normal teardown path. Cleaner and less code than replicating the native wrapper.
- **`abort()` = `AbortController.abort()` only** (synchronous, idempotent via a `_torn` flag). The browser-level abort cancels the in-flight fetch + errors the stream; the returned future settles immediately, so the watchdog never waits on it.
- **A genuine mid-stream `read()` rejection is rethrown** (→ classifier → `transportClosed`); a rejection *after* we aborted is swallowed (it is teardown, not a failure). Distinguished by the `_torn` flag.

**Deviations from the story's literal text (surfaced, not silent):**
1. **`@TestOn('vm')` added to 9 native suites.** The story's Task 4 says the web job runs `cd packages/koel_http && dart test -p chrome`, and the coverage `with_chrome` pass runs the same — but the native `dart:io` suites have no platform annotation, so Chrome tries to compile them and fails. The idiomatic complement to the new `@TestOn('browser')` web suite is to mark the `dart:io` suites `@TestOn('vm')` so Chrome cleanly *skips* them. This makes the story's verbatim command work and is the established pattern for Epic 6/8 web tests. (`pii`/`sentry` suites import no `dart:io` and run on both platforms harmlessly — not annotated, since claiming they need the VM would be false.)
2. **Coverage merge mechanics.** The story sketched "two passes into the same `coverage/` dir + one `format_coverage` reports the union." That double-counts cross-platform-loaded files (see Debug Log). The honest union is per-file max-hit dedup with branch from the VM pass — documented in `tool/coverage.sh`. The *outcome* the story wanted (web_transport covered for real, branch scoped to the VM surface, gate meaningful across both transports) is delivered.
3. **`comment_references` stragglers fixed across ~10 pre-existing 4.1–4.9 `lib/` files** (+ `TracePhase` enum-value docs for `public_member_api_docs`). The member-doc gate had never run on koel_http, so prior stories' `[filename.dart]`/prose `[param]` doc refs (which don't resolve as symbols) surfaced. Converted to backticks (koel_core's clean style). The package now analyzes to **0 issues**, matching koel_core's flagship bar — not just `dart analyze` exit 0.
4. **One pause/resume backpressure test added** (`http_agent_test.dart`) to lift branch coverage over the 90% kernel-tier bar (the `onPause`/`onResume` handlers in the `abortOnCancel`/lifecycle wrappers were never exercised; koel_http was never branch-gated before this story). Final branch 92.06%.
