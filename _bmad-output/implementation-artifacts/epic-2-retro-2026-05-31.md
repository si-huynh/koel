## What Went Well

1. **The sealed-union + freezed classic-parts idiom — established once, reused 30+ times.**
   Story 2.2 worked out the only layout satisfying `sealed` + separate-file subtypes under the analyzer-12 pin (single library root + all subtypes as `part of`, one shared `ag_ui_event.freezed.dart`). 2.3 (`KoelError`), 2.4 (`JsonPatchOp`), and 2.5–2.8 (all 28 event types) reused it verbatim. 2.8 put it plainly: *"you are copying a proven pattern twice, not inventing anything."* Velocity climbed toward the end of the epic as a result.

2. **Retro lesson A1 ("verify the toolchain, don't assume") became muscle memory.**
   The "retro A1" tag appears across 2.1/2.2/2.3/2.4/2.7 — every freezed/codegen claim was verified by running `build_runner`, not assumed. 2.1 explicitly framed its toolchain conflict as "retro lesson A1 in the flesh." Near-zero unverified-toolchain assumptions slipped through.

3. **Review hardened the contract beyond the ACs — and generalized the fix.**
   A recurring review theme: a raw error escaping the typed codec boundary. SF-1 (2.5: `_TypeError` instead of `ProtocolError`) → extended to `Message.fromJson` (2.6, `_decodeObjectList`) → extended to bool/base64 (2.7, `_optionalBool`/`_decodeBase64`). Each fix *generalized the guard* rather than point-patching. Reviews consistently PASSED ACs yet still made the kernel more robust.

4. **Scope discipline: the barrel stayed frozen until 2.15.**
   Every story 2.2→2.14 explicitly confirmed `lib/koel_core.dart` untouched; 2.15 populated the entire public surface in one dedicated pass. The one-way-door decision was deferred to a single story — clean, no churn.

5. **Framework-source-depth wins.** 2.11 caught an `async*` + `await for` pipeline that **deadlocked on `cancel()`** over an idle upstream (the "stranded cancel" DD8 forbids), and pivoted to an explicit `StreamController` (`buildStage`/`stage_support.dart`) with deterministic pause/resume/cancel. This is exactly the runtime-cost / lifecycle rigor the `/agent-flutter-engineer` mandate exists for.

## Challenges & Patterns

### Challenge 1 — The analyzer-12 stopgap (largest carried toolchain debt)
Epic 1's spike #1 (pivot to `analysis_server_plugin`) resolved the lint mechanism but surfaced a new constraint: asp pulls `analyzer ^13`, which conflicts with `freezed` (`analyzer <11`). Story 2.1 had to pin **`freezed 3.2.6-dev.1` + asp 0.3.14 + analyzer 12.1.0** (SCP-2026-05-29-B). This also *shaped the architecture* — 2.2 was forced into classic-parts for the sealed union because analyzer-12 rejects enhanced parts. The whole event layer now rides on a dev-version pin with a documented upgrade trigger. (Project memory: lint pivot to analysis_server_plugin.)

### Challenge 2 — Session-lifecycle / concurrency cluster (largest deferred cluster)
`ChatSession` (2.14) has no reliable "a run is in flight" predicate (`_sub`/`_completer` never nulled on completion), so concurrent `send()`, `clear()` mid-run, and `cancel()` after completion all misbehave. All 2.14 ACs pass; these are robustness gaps no AC exercises. Correctly parked wholesale to Epic 6 `6-1 KoelChatController` — but it is load-bearing for any real UI.

### Challenge 3 — Carried Epic-1 item D4 not yet closed
Dart floor `3.9.0` vs `pubspec.lock` `3.10.0`. Low impact while solo; bites a fresh contributor or a mis-pinned CI. Carry-forward.

### Challenge 4 (process) — Story specs repeatedly under-specified; dev corrected in-flight
2.2 (sealed-union layout wrong in Dev Notes), 2.4 (pointer placement), 2.5/2.6 (codec error boundary the ACs missed). This is the *same* root as Epic 1's Challenge 1 (spec drift from toolchain reality) — but now caught cheaply because A1 is internalized. `create-story` encodes plausible-but-unverified mechanics; `dev-story` corrects them. The mechanism works, but story specs are not trustworthy as-is — verify-by-running remains mandatory.
