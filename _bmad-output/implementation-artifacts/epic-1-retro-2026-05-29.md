## What Went Well

1. **Spec-driven discipline with documented deviations.** Every story that hit a wrong spec fixed it in-place *and* recorded the rationale. Examples:
   - Story 1.3 discovered `package:lints/strict.yaml` never shipped in any `lints` version (1.0.1 → 6.1.0) → switched to `recommended.yaml`, logged 4 deviations.
   - Story 1.1 discovered Melos 7.x reads scripts from `pubspec.yaml > melos.scripts`, not `melos.yaml`.
   - The spec was treated as a map, not the territory.

2. **`deferred-work.md` as a living ledger.** Every postponed item was routed forward with an owning story + re-verify condition, and closed explicitly. Story 1.6 closed 9 Epic-1 items and listed 4 carry-forwards. Functions as a real risk register, not a TODO list.

3. **Adversarial review with high signal-to-noise.** Story 1.3: 58 findings → 1 patch + 1 decision + 12 defer + 44 dismissed (spec-compliant). High dismiss rate = review caught real issues without noise.

4. **A genuinely green baseline.** Not green-on-paper: `melos bootstrap` (11 packages), analyze clean, format:check clean — verified repeatedly across stories.

## Challenges & Patterns

### Challenge 1 — Spec drift from toolchain reality (recurred in 1.1, 1.2, 1.3, 1.4)
Systemic, not isolated. Root cause: the planning layer (PRD/architecture/epics) was authored before touching the real toolchain, so it encoded unverified version/API assumptions:
- `package:lints/strict.yaml` referenced in AC1, AC4, Task 3.1, Task 6.1, and `architecture.md:1163` — file does not exist.
- Story 1.3 AC2 omitted the `lints` dev-dep needed to resolve its own `include:`.
- Spec assumed Melos scripts live in `melos.yaml`; reality is `pubspec.yaml`.
- Spec 1.2 suggested adding `koel_lints` as a `path:` dep — pub workspace forbids path-deps targeting workspace members.

The dev caught all of these. The cost was iteration loops, and the risk is Epic 2 (real freezed/build_runner codegen) carrying the same class of assumption at higher cost.

### Challenge 2 — `custom_lint` 0.8.1 + pub-workspace: principal rule does not fire on consumer source 🚨
The SDK's principal lint rule — `exhaustive_switch_must_have_default`, the reason `koel_lints` exists (FR-A12 / FC-2) — does **not** trigger on consumer source.
- It runs correctly in `koel_lints` unit tests (4/4 green via `testAnalyzeAndRun`).
- Via `include: package:koel_lints/koel.yaml` in a consumer package, the rule is silently skipped. The dev record attributes this to `custom_lint` 0.8.1 reading `package_config.json` from each member's empty `.dart_tool/` in pub-workspace mode (`workspace.dart:333-341`).

**Project Lead's correction (important):** the current "confirmed custom_lint bug" conclusion is itself an *unverified assumption*. The dev record only proves the *symptom* (rule doesn't fire via the consumer path), not that the root cause is upstream rather than our own wiring. Since `melos` + `custom_lint` is a very common Flutter monorepo combo (riverpod, etc.), if it were fully broken in workspace mode the community would have surfaced it loudly. → This is now an **investigation spike**, and the ledger entry must be downgraded from "confirmed bug" to "unverified hypothesis" until community evidence exists.

### Challenge 3 — Toolchain version drift
- Packages scaffolded with Dart 3.12 while declared floor is 3.9.0.
- `pubspec.lock` resolves `sdks.dart: ">=3.10.0"` (raised by a transitive dep), contradicting the `.tool-versions` pin `3.9.0`. A fresh contributor on exactly 3.9.0 may fail `pub get`.

## Significant Discoveries Affecting Epic 2 (`koel_core`)

Epic 2 is the first real-code epic: 15 stories, freezed/build_runner codegen, sealed `AgUiEvent` (~28 types), sealed `KoelError`, inline RFC 6902, 4-stage pipeline, coverage ≥ 90%.

| # | Discovery from Epic 1 | Impact on Epic 2 |
|---|---|---|
| D1 | `codegen-drift.yml` runs `git diff --exit-code`, but `.gitignore` excludes `*.g.dart`/`*.freezed.dart` repo-wide; `git diff` inspects only tracked files. | When Story 2.1 adds freezed codegen, generated output is gitignored → the drift gate **won't catch drift**. Fix: un-gitignore for the CI lane OR switch to `git status --porcelain` over untracked generated paths. |
| D2 | `format:check` runs `dart format ... .` (whole package incl. `lib/`). | Once codegen lands in `lib/`, format:check walks generated files. build_runner output is usually format-stable but not guaranteed → spurious gate failure. Fix: exclude generated paths. |
| D3 | `custom_lint` rule does not guard consumer source (hypothesis — needs investigation). | Epic 2 defines exactly the sealed unions the rule exists to protect. If unresolved, FC-2 (adding a subtype = semver-minor) is not automatically enforced. |
| D4 | `pubspec.lock` floor `dart >=3.10.0` contradicts `.tool-versions` pin `3.9.0`. | A new contributor (or mis-pinned CI) may fail `pub get`. Resolve before broadening team/CI matrix. |

**Epic Update Required:** Minor — no Epic 2 *story* needs rewriting, but Story 2.1 must absorb D1+D2 fixes, and spike #1 (D3) should land before `sealed AgUiEvent` is written. Also a doc-hygiene erratum pass (Challenge 1).
